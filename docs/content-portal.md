# Content portal (wayneomni.com/admin/)

The content portal is Decap CMS at `/admin/`, logged in with GitHub. Every save becomes a
commit or pull request in this repo, and Cloudflare Pages rebuilds the site after a merge.

## What you can edit

| Section | What it controls | File |
| --- | --- | --- |
| Page SEO | Title and meta description of Home, About, AI Agents, AI Visibility, Services, Insights, Work, Contact | `src/data/pages.json` |
| Services | Service page copy, plus SEO title / SEO description per service (incl. Google, Meta, TikTok Ads) | `src/content/services/*.md` |
| Insights | Articles: category, dates, author, draft switch, SEO title / description, body | `src/content/insights/*.md` |
| Site settings | Brand, contact, analytics IDs, show/hide portfolio | `src/data/site.json` |

Titles get " — Wayne Omni" added automatically. Aim for 50–60 character titles and 140–160
character descriptions. An empty SEO field falls back to the page title / intro / excerpt.

## Review queue (editorial workflow)

`/admin/#/workflow` has three columns: **Drafts**, **In review**, **Ready**. Each card is an open
pull request. Clicking **Publish** merges the pull request into `main`, which deploys the site.

### How agents put articles into the review queue

Decap only shows a pull request in the queue when all of these are true:

1. The branch is in this repo (not a fork) and named `cms/insights/<slug>`.
2. The pull request targets `main`.
3. It carries one status label: `decap-cms/draft`, `decap-cms/pending_review` or
   `decap-cms/pending_publish`. Agents should use `decap-cms/pending_review`.
4. It changes `src/content/insights/<slug>.md` (plus any images under `public/uploads/`).
   One article per pull request.

The frontmatter must use the Insights fields above, with `category` set to one of:
Google Ads, Meta Ads, TikTok Ads, Website Development, Lead Generation.

Example:

```bash
git checkout -b cms/insights/meta-ads-lead-forms-malaysia
# add src/content/insights/meta-ads-lead-forms-malaysia.md
git push -u origin cms/insights/meta-ads-lead-forms-malaysia
gh pr create --base main --title "Create Insights “meta-ads-lead-forms-malaysia”" \
  --body "Automatically generated by Decap CMS" --label decap-cms/pending_review
```

Pull requests that do not follow this pattern still work on GitHub; they just do not appear
in the portal.

## Login setup (one-time)

Login uses two Cloudflare Pages Functions in this repo: `functions/api/auth.js` and
`functions/api/callback.js`. They need a GitHub OAuth app:

1. GitHub → Settings → Developer settings → OAuth Apps → New OAuth App.
   - Application name: `Wayne Omni CMS`
   - Homepage URL: `https://wayneomni.com`
   - Authorization callback URL: `https://wayneomni.com/api/callback`
2. Copy the Client ID. Click **Generate a new client secret** and copy it.
3. Cloudflare dashboard → Workers & Pages → `wayne-omni` → Settings → Variables and Secrets
   (Production): add `GITHUB_CLIENT_ID` (text) and `GITHUB_CLIENT_SECRET` (secret).
4. Redeploy (or merge any change). Then open `https://wayneomni.com/admin/` and click
   **Login with GitHub**.

Only GitHub accounts with write access to this repo can save anything.
Login works on `wayneomni.com` only, not on `*.pages.dev` preview links.

## Local editing

`pnpm cms` (decap-server) plus `pnpm dev`, then open `http://localhost:4321/admin/`.
